OSUZ V36 deployment notes

1. /product/<slug>-<id> and /catalog/<slug>-<id> are served by backend routes/seo.js as described in the developer document.
2. Rebuild/redeploy the backend after replacing product.html/category.html because those files are copied into the backend image.
3. Keep only one <title> in product.html/category.html. Backend injects description/canonical/Open Graph/schema for those clean URLs.
4. /category.html?q=... remains the search URL.
5. robots.txt belongs in the public site root. sitemap.xml is generated by backend; do not deploy a static sitemap.xml.
6. On localhost/127.0.0.1, routing helpers intentionally fall back to legacy .html?id=... links so VS Code Live Server can open pages without backend clean-route rewrites. Production uses API entity.url directly.

V37 SESSION FIX
- Local development now normalizes 127.0.0.1/0.0.0.0 to localhost so localStorage auth is not split between origins.
- Background cart/header token refreshes never erase login state on transient network/CORS/5xx failures.
- Profile renders cached customer immediately and verifies /me in the background.
- Session is cleared only after a confirmed 401/403 from auth refresh or /me retry.
- Rotated refreshToken from /refresh is persisted when returned.

V38 session hardfix (2026-09-12)
- Login now always persists a cached customer fallback plus tokens.
- Cached account is shown immediately on auth.html; /me only refreshes data in background.
- Stale registration/password-reset sessionStorage no longer overrides an existing account.
- cart.html and orders.html no longer erase osuzCustomer on background refresh failures.
- Invalid refresh tokens remove only tokens; cached profile remains until explicit logout/delete/password reset.
- Explicit logout/delete account still clears the full local session.
